## Caller, undo, mirror, and persistence closure

1. `ConnectionPixmapItem::itemChange` snaps drag movement to the metatile grid and commits `MapConnectionMove` through the connection’s parent map only when its offset changes. Its mouse-release action ID separates drag sessions. `ConnectionsListItem` commits direction, target-map, move, and removal commands to its parent map; its valid-map selection is restricted to the supplied map-name list, and its move action ID advances at editing completion. `Editor::addNewConnection`, `replaceConnection`, and `removeConnection` are additional command producers, retained as reused context.
2. `Map::commit` pushes to one map’s `QUndoStack`; `Editor::setMap` selects the active map stack. `Editor::unsetMap` calls `Map::pruneEditHistory` before changing maps. The connection commands snapshot the mirror-enabled setting when constructed. Move merging requires the same connection and action ID. Direction/map edits retain old values and reset offsets when their prior offset no longer has the same meaning. Add/remove keep pointers in `QPointer` fields, and `Map` retains removed connection objects for undo. `MapConnectionMove` instead stores a raw connection pointer; the model’s map ownership is therefore part of its safety condition.
3. Mirroring is value-based, not a durable pair identity: `findMirror` compares parent/target names, opposite direction, and negated offset, and the source explicitly notes that identical duplicates can make the chosen counterpart non-deterministic. Add/remove re-find a counterpart when the retained one no longer matches. The test covers ordinary unique pairs only.
4. A mirrored setter mutates the counterpart and emits `Map::modified` on each owning map. `Project::loadMap` emits `mapLoaded`; `MainWindow::onMapLoaded` subscribes to `Map::modified`, and `markMapEdited` sets `hasUnsavedDataChanges`. Therefore the mirror map does become dirty; it is not merely a title-bar notification. `Project::hasUnsavedChanges` includes every map’s dirty state.
5. `Editor::save(true)` routes through `Project::saveMap(this->map)`, whereas `Editor::save(false)` routes through `Project::saveAll`. The per-map writer serializes that map’s own `getConnections()` list and calls `map->setClean()` after its JSON dump; `Project::saveAll` iterates the project map collection. Consequently a successful **Save Current** can leave the mirrored counterpart dirty and unwritten; the project-level dirty state remains set. The test uses a stub for Project save routing and does not write or compare JSON bytes.

## Source objection: masked connection IDs evade history pruning

`MapConnectionMove`, `MapConnectionChangeDirection`, `MapConnectionChangeMap`, `MapConnectionAdd`, and `MapConnectionRemove` all return their base `CommandId` ORed with `getConnectionDirectionMask(...)`. For normal directions that mask is nonzero (bits 8–13). `Map::pruneEditHistory` builds a set containing only the unmasked base IDs, then performs exact `mapConnectionIds.contains(command->id())` comparison. Thus a normal masked connection command does not match the set and is not marked obsolete when `Editor::unsetMap` asks to prune it.

The bounded native Qt witness compiled the unchanged pinned command bodies and `Map::pruneEditHistory` with real `QUndoStack`, plus test-only `Map`, `Project`, `Editor`, and `MainWindow` shells. It reproduced: an A→B move; the prune call leaves A’s masked command non-obsolete; a subsequent move from B changes the same pair; undoing A’s retained command overwrites that B edit; undoing B then restores its own recorded old value. This is direct evidence of the pinned method behavior and a plausible stale-history conflict, not a simulated full `Editor::setMap` interaction. The exact source mutation controls reject removal of the ID mask, a masked-ID-prune “fix,” altered mirror/undo operations, removed dirty-state wiring, and changed save routing.

The same Qt run called the unchanged `MainWindow::onMapLoaded`, `markMapEdited`, `Editor::save`, `Project::hasUnsavedChanges`, Map dirty-state methods, and connection command/model method bodies. It observed both maps becoming dirty after a mirrored edit and the test-only current-save boundary cleaning only the active map while leaving its counterpart dirty. Add/remove and direction/map command undo/redo were also exercised. This is compiled method-level evidence only: the Project loader/save stubs do not implement upstream file parsing or writing.
