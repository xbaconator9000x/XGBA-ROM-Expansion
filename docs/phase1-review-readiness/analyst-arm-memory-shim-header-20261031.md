## Known preconditions, counterexamples, and reviewer objections

- The functions dereference `debugger` and `debugger->cpu` without explicit null checks. They require an initialized, live debugger and CPU; calling with null or uninitialized pointers is not safe by source inspection. Do not label these calls generally safe.
- **Install is not idempotent.** Calling it twice without an intervening remove overwrites `originalMemory` with the already-installed shim pointers. Subsequent wrapper delegation could recurse. The observed intended caller installs only on a transition from zero to one watchpoint, and removes on last watchpoint/deinit. This is a **source-level precondition**, not a tested guarantee under every lifecycle or reentrancy.
- `RemoveMemoryShim` restores the snapshot unconditionally; calling it before initialization or after unrelated memory-table modifications may overwrite live handlers. The observed init captures an initial snapshot, but correctness for arbitrary external caller sequences is not established.
- The wrapper's component lookup can abort when no debugger component is found; watchpoint condition evaluation and `originalMemory` delegation may have further runtime/ABI conditions. These belong to the implementation and are not claims made by the two-line declaration interface.
