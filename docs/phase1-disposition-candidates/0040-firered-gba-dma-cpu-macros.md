## Whole-file macro inventory
- Include guard. `CPU_FILL` and `CpuFill16/32` use a volatile local source and `CpuSet` with source-fixed and 16/32-bit transfer flags. `CPU_COPY` and `CpuCopy16/32` use `CpuSet`. The size argument is divided by element width and masked to 21 bits. `CpuFastFill`, `CpuFastFill16/8` and `CpuFastCopy` use `CpuFastSet` with 32-bit transfer-count conversion; caller alignment, size rounding and BIOS transfer rules are not checked by these macros.
- `DmaSet` token-pastes a DMA channel number into `REG_ADDR_DMA##dmaNum`, writes source/destination/control as three 32-bit registers and reads back control. `DMA_FILL`, `DmaFill16/32`, `DMA_CLEAR`, `DmaClear16/32`, `DMA_COPY`, `DmaCopy16/32` set immediate-start DMA flags and convert byte size to halfword/word counts. `DmaStop` clears start/repeat/enable bits through halfword registers.
- `DmaCopyLarge`, `DmaClearLarge`, `DmaFillLarge` and their 16/32-bit wrappers use a `while(1)` full-block loop followed by a residual transfer. All three **issue a full `block` transfer before testing the remaining `_size`**; they decrement a `u32` count by `block` first. A caller with `size < block` (including zero) therefore violates the loop's implicit precondition and may underflow `_size`/request excess DMA. This is a source-level boundary hazard; **actual call-site reachability, compiler execution and hardware impact have not been tested**. The macros also perform arithmetic on `void*` pointers, requiring a compatible compiler extension.
- `DmaCopyDefvars`, `DmaFillDefvars`, `DmaClearDefvars` and 16/32 wrappers create local aliases for operands before dispatching. `IntrEnable(flags)` temporarily disables `REG_IME`, ORs `flags` into `REG_IE`, then restores the prior IME value; this does not prove IRQ scheduling, latency or vector lifetime.
