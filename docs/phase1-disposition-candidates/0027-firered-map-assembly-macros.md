## Entire authored macro inventory
- `map` emits map group as `map_id >> 8` and map number as `map_id & 0xFF`, one byte each. `map_script` emits one type byte followed by a 4-byte script reference (5 authored bytes); `map_script_2` emits two 2-byte fields and a 4-byte script pointer (8 bytes). Caller-side alignment and table termination are not established by this file.
- `object_event` emits a 24-byte normal object template: local index, graphics, normal-kind byte, padding, 16-bit coordinates, elevation, movement, packed 4-bit X/Y radii, padding, two 16-bit trainer fields, 32-bit script reference, 16-bit event flag and final padding. `clone_event` also emits 24 bytes, but stores clone target map number/group as **two 16-bit halfwords**, not the `map` macro's pair of bytes, and leaves 8 trailing bytes. Both increment `_num_npcs`. The 4-bit radius and map-ID widths have no explicit range validation here.
- `warp_def` emits an 8-byte warp (two 16-bit coordinates and four 1-byte fields: elevation, warp ID, map number, map group) and increments `_num_warps`. `coord_event` emits a 16-byte coord record (coordinates, elevation, padding, var, compare value, padding, script pointer) and increments `_num_traps`. `coord_weather_event` forwards to `coord_event` with weather in the var slot, compare=0 and NULL script; its comment says FRLG weather handlers are dummied out, which needs external confirmation.
- `bg_event` emits 12 bytes: two 16-bit coordinates, elevation and kind bytes, two padding bytes, and either one 32-bit argument or a hidden-item payload of 16-bit item, 8-bit flag offset and 8-bit packed quantity/underfoot. `bg_sign_event`, `bg_hidden_item_event` and `bg_secret_base_event` are wrappers; secret base is documented unused in FRLG. `bg_hidden_item_event` subtracts `FLAG_HIDDEN_ITEMS_START` and shifts underfoot into bit 7; no overflow/underflow or collision guard is authored here. All backgrounds increment `_num_signs`.
- `map_events` emits four **one-byte** counts plus four 32-bit pointers (20 bytes), then calls `reset_map_events`; the latter sets all four assembler counters to zero. An initial reset is invoked at file scope. Counter overflows and emitted pointer layout require assembler/ELF checks.
- Six `connection_*` aliases map down/up/left/right/dive/emerge to south/north/west/east/dive/emerge constants. `connection` emits one direction byte, 3 padding bytes, a 32-bit offset, two map-ID bytes through `map`, and 2 trailing padding bytes (**12 bytes**). It does not prove signed-range validation of offsets.
- `map_header_flags` emits **two bytes**: raw `allow_cycling` followed by packed bit 2 `show_map_name`, bit 1 `allow_running`, bit 0 `allow_escaping`. Only the last three are masked to one bit in this macro.

## Cross-file and expansion implications
The header comment identifies `tools/mapjson` as the generator for most directives. Source contracts to check against `include/global.fieldmap.h`: ObjectEventTemplate, WarpEvent, CoordEvent, BgEvent, MapEvents, MapConnection, MapHeader. Constant dependencies include map IDs, object kinds, BG_EVENT_*, hidden-item flag base, connection enums, script types and NULL. Expansion/round-trip tooling must retain source JSON provenance and the distinctions between byte-sized IDs, clone target halfwords, packed flags, padding, counter scope and pointer widths. Do not infer that unused padding is available for XGBA metadata or that a pointer is remappable across ROM banks.
