## Full-function semantic inventory (1-based pinned source anchors)
- **I/O and serialization helpers (36–120):** `read_text_file` opens a file, seeks to end, resizes string to `tellg()`, reads bytes and closes; `write_text_file` opens binary output, streams the text and closes. They error on open failure but do not locally check seek/read/write completion. `json_to_string` converts JSON string, integer-valued number and boolean (as `TRUE`/`FALSE`), returns empty for null, and errors on unsupported types or empty values unless `silent`. `get_generated_warning` emits a source provenance comment; `get_include_guard_start/end` form C header guards. Globals `version` and platform separator `sep` influence all modes.
- **Per-map header (122–186):** requires exactly one layout ID match in `layouts_data["layouts"]`, emits layout pointer, optionally shared events/scripts map pointers, conditional connections pointer, music/layout ID, region/flash/weather/map type, and version-specific flag/extra bytes. A nonempty connections JSON array can still produce a null header pointer when `connections_no_include` stringifies to `TRUE`. Ruby emits `show_map_name` byte; Emerald/FireRed emit `map_header_flags`; FireRed adds floor number; non-FireRed adds two bytes of padding. No final linked offsets are proved here.
- **Per-map connections (188–210):** null JSON `connections` returns only newline; otherwise emits each `connection direction, offset, map` directive in source array order, then a 32-bit count and list pointer. An empty but nonnull array emits an empty list label/count while the header generator emits a null connection pointer. Source JSON authoring and native reachability therefore differ.
- **Per-map events (212–353):** `shared_events_map` suppresses local event emission. Otherwise emits aligned normal or clone object templates (local ID assigned **array index + 1**, regardless of type), warp templates, coord triggers/weather, and BG sign/hidden item/secret base events; rejects unknown event types. Empty arrays use `NULL` table pointers. FireRed hidden-item directives additionally pass quantity and underfoot. Ends with `map_events` counter/table macro. The generator is not a range validator for packed fields; the assembler macro owns their byte widths.
- **Path and map orchestration (355–392):** strips a final slash/backslash, infers separator from input path, computes parent path, parses map/layout JSON and writes `header.inc`, `events.inc`, `connections.inc`. `strip_trailing_separator` calls `.back()` without an explicit empty-string guard; `infer_separator` indexes `filename[dir_pos]` without checking `npos`. Whether valid CLI inputs trigger either condition is not established.
- **Generated event IDs (394–434):** parses all supplied map JSONs, emits a guarded `map_event_ids.h`; optional `local_id` macro names get **1-based object/clone array positions**, optional `warp_id` names get **0-based warp positions**. This proves that the included `constants/map_event_ids.h` is a build product, not a fixed upstream Git blob. It does not check duplicate macro names or collisions across map files.
- **Map groups/ordering (436–587):** `generate_groups_text` emits per-group header pointer arrays and `gMapGroups`; `generate_connections_text` flattens `group_order` and optionally sorts map names according to `connections_include_order`; `generate_headers_text` and `generate_events_text` emit per-map include directives. `generate_map_constants_text` reads each map JSON ID and assigns map IDs as `map_index | (group_index << 8)`, then emits `MAP_GROUPS_COUNT`. `process_groups` writes four assembler includes and `map_groups.h`.
- **Layouts (589–673):** `generate_layout_headers_text` emits binary border/blockdata `.incbin` assets and a six-word layout record; FireRed adds two border-dimension bytes and a zero halfword. Empty JSON objects are skipped. `generate_layouts_table_text` emits a pointer per layout entry, `NULL` for empty entries. `generate_layouts_constants_text` assigns **1-based IDs**, incrementing even for empty entries, preserving holes. `process_layouts` writes two assembler includes and `layouts.h`.
- **CLI dispatch (675–740):** validates version in `emerald/ruby/firered`, dispatches exactly four modes `map`, `groups`, `layouts`, `event_constants` with distinct argument-count requirements and paths, then returns zero. Unknown versions/modes terminate with fatal errors.

## New source-level hazards for independent review (not reproduced failures)
1. **Potential undefined iterator arithmetic in optional connection sorting:** at lines 470–479, absent names in `connections_include_order` are represented by `connections_include_order.begin() + numeric_limits<int>::max()`. Forming an iterator that far beyond the container is not valid standard C++ pointer/iterator arithmetic; the comparator then orders those values. Whether this causes an observed mis-sort or crash depends on actual input and implementation. Test omitted/partial order lists with sanitizers and check generated connection include order before proposing a fix.
2. **Generated-ID namespace collisions:** event constant names are taken verbatim from optional `local_id`/`warp_id` fields without an explicit duplicate-name check in this function. Confirm collisions and compiler diagnostics in a controlled fixture; preserve per-map source provenance and array-index semantics.
3. **Width and order contracts:** map IDs encode 8-bit group/index components in constants; object/warp local IDs derive from order; assembler emits one-byte event counts and 32-bit pointers. The generator does not itself prove that out-of-range input is rejected or that compiled/ROM/editor round trips preserve authored metadata.
4. **I/O and path preconditions:** missing local read/write completion checks and unguarded string indexing are source-level proof obligations, not confirmed reachable faults.
