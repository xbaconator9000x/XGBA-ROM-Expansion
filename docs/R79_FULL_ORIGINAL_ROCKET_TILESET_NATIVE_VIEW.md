# R79 — Rocket group 35:0 original source tile capacity recovery

Original full SHA-pinned Rocket v3.06 source descriptor `0x00ea0300` has a null original tileset animation callback and 480 compressed source 4bpp tiles. All 196 authentic static metatile definitions refer only to secondary tile indexes 0–341 (max global 981). A physically valid original Emerald 640/384 BG primary/secondary split can therefore render the 384 first tiles without losing *any static metatile referenced art*. The source's complete 480 tiles (full SHA `e850da1f22da1b3bff80750b1c2c65d4607589681d2c9189b39d1719eede7835`) remain **unaltered** in the private pack as separate authenticated full-image and surplus-tail resources. The native R53 view stores 384 exact original first tiles, with original metatiles, attributes and palettes and CRC on each section. This is **render-window compaction**, not invention or mutation of the original artwork.

The public R79 builder fails closed on nonmatching whole-ROM SHA, full-graphics SHA, mismatched descriptor, non-null tileset animation callback, source metatile referencing tile >=384, mismatched metadata spans, bad output SHA or duplicate original IDs. Public tests use entirely authored graphics only. No private GBA, original pixels, private ZIP or save files are added to GitHub.

**Limits:** a null tileset callback and bounded source metatiles do not prove that arbitrary foreign-world scripts never DMA graphics into currently unused slots, so dynamic tile writes or battle/scroll behaviour need emulator evidence. The three-room first-hop private source render closure is no longer blocked by simple static tile capacity, but real physical GBA same-world door transitions and three-game Fly still need original source-world map activation, original scripts, Flash namespace and real LCD validation.
