# R84 — Prevent foreign world native Flash save corruption

Native Emerald Flash `gSaveBlock1Ptr->location` records a real Emerald group and map, but the R80 original source-world route uses Emerald's temporary group 0/map 9 renderer for Rocket group35 interiors. Original source world/group/map identity is transient and deliberately is **not a persistent original-source-world save** yet. A normal native Flash save would permanently store the *wrong world's* location and restore the player into actual Emerald Littleroot on cold restart.

R84 fails closed: while any original R80 source-world room/door transition is active, any original R48 pending foreign Fly is in progress, or the native R50 foreign map renderer is active, the actual original Emerald `src/save.c` core `HandleSavingData` transaction and player `TrySavingData` are refused **before any flash write or save counter update**. The player path returns `SAVE_STATUS_ERROR`, not a fake success. Direct original incremental link-save, sector replacement and block-save writer entry points are likewise guarded, returning original failure/abort sentinel `TRUE`. Source0 original Emerald saves remain exactly vanilla with original R18 Flash/cold continue intact. All R84 save patches are explicitly activated only for the real R54 native multiworld build.

This protects the already-existing save against a wrong-world write, but does NOT implement true original Rocket or Heart & Soul Flash persistence. That requires a versioned, source-qualified auxiliary save protocol paired transactionally with native Emerald's rotating sector counter, original world/map location, party/PC and story state, and save interruption tests. No native Flash sectors or original source data are repurposed. PR stays draft until authentic private-ROM emulator playthrough, native Flash persistence and all three world assets are proven.
